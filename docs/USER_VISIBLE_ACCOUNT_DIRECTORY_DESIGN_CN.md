# 用户可见账号目录设计

## 1. 目标与边界

用户端的“账号目录”是一个**只读、按权限裁剪的运行信息视图**，用于让用户了解自己可见分组中的账号容量、可用性和用量概况。它不是管理员账号管理的降级拷贝，更不是一个可探测上游资源的接口。

本设计解决三个需求：

1. 所有已登录用户都能看到活跃的公开分组及其未被独占租约占用的账号。
2. 用户只有在具备当前分组访问资格时，才能看到属于自己的专属分配账号；订阅型分组还必须存在有效订阅。
3. 用户可以像查看账号管理列表一样检索、筛选、切换行/网格视图和查看详情，但页面不存在任何账号操作入口。
4. 管理员可为一个专属分组的合格用户整体开放缓存用量细节，也可只为一个用户开放一个可见账号的缓存用量细节。

目录仅承担“可见性说明”，不改变 API Key 绑定、请求调度、订阅校验、账号分配或管理员控制面的既有规则。

## 2. 可见性与访问授权

“能在目录中看到”与“能向该分组发起请求”是不同概念。目录不会授予 API 权限；网关和 API Key 仍按既有分组/订阅规则认证。

| 账号来源 | 目录可见条件 | 基础用量口径 | 上游缓存用量细节 |
| --- | --- | --- | --- |
| 公开分组账号 | 分组活跃、未删除、`is_exclusive=false`、账号未删除且未被任何活跃分配租约占用 | 同一账号在同一分组的近 24 小时聚合 | 仅管理员建立“指定用户 + 分组 + 账号”授权后显示 |
| 专属分组共享账号 | 用户仍具备专属分组权限或有效订阅，账号未被独占租约占用 | 同一账号在同一分组的近 24 小时聚合 | 专属分组整体授权或“指定用户 + 分组 + 账号”授权后显示 |
| 标准专属分组分配 | 当前用户拥有活跃分配，分组和账号仍活跃，且用户仍被允许使用该专属分组 | 当前用户从本次分配开始的个人聚合 | 活跃分配自动显示 |
| 订阅型专属分组分配 | 满足标准专属分配条件，并且当前用户有未过期的活跃订阅 | 当前用户从本次分配开始的个人聚合 | 活跃分配自动显示 |

公开分组即使具有订阅计费属性，仍可作为公开目录条目展示；这满足“所有用户能看到公开分组”的产品定义。未订阅用户依然不能据此绑定 API Key 或绕过网关订阅校验。

## 3. 服务端安全模型

### 3.1 独立只读接口

新增接口：

```text
GET /api/v1/account-allocations/visible
```

旧接口 `GET /api/v1/account-allocations` 保持不变，供已有“我的分配摘要”调用使用。新接口不接受用户 ID、分组 ID 或账号 ID 参数；用户身份完全由 JWT 中间件提供，避免越权枚举。

### 3.2 严格白名单 DTO

接口仅返回以下字段：

```json
{
  "items": [
    {
      "view_key": "visible-dedicated-1",
      "source": "dedicated",
      "usage_detail_access": "assignment",
      "group_id": 42,
      "group_name": "VIP OpenAI",
      "subscription_type": "subscription",
      "account_name": "a***e@example.com",
      "account_name_masked": true,
      "platform": "openai",
      "account_type": "oauth",
      "capacity": { "concurrency": 3 },
      "status": "ready",
      "usage": {
        "scope": "personal_lease",
        "request_count": 128,
        "total_tokens": 345678
      },
      "upstream_quota": {
        "updated_at": "2026-07-23T11:55:00Z",
        "five_hour": {
          "utilization": 35,
          "resets_at": "2026-07-23T15:00:00Z",
          "window_stats": {
            "requests": 63,
            "tokens": 1600000,
            "cost": 0.65,
            "standard_cost": 0.60,
            "user_cost": 0.65
          }
        },
        "seven_day": { "utilization": 12, "resets_at": "2026-07-30T10:00:00Z" }
      },
      "assigned_at": "2026-07-23T10:00:00Z"
    }
  ],
  "summary": {
    "public_group_count": 2,
    "dedicated_group_count": 1,
    "public_account_count": 8,
    "dedicated_account_count": 2,
    "ready_account_count": 7
  }
}
```

以下字段永远不进入此 DTO：

- `account_id`、`assignment_id`、`policy_id` 及其他后台操作标识；
- 凭据、PAT、OAuth 数据、会话、代理、IP、备注、上游错误原文；
- 可用模型列表、优先级、调度权重、风控状态、其他用户信息；
- 跨分组或跨用户的历史明细。

`view_key` 仅为当前响应的前端渲染键，不包含或映射为账号 ID。

`usage_detail_access` 只可能为：

- `assignment`：当前用户自己的活跃专属分配；
- `group`：管理员对当前专属分组整体授权；
- `direct`：管理员对当前用户、分组和账号精确授权。

`upstream_quota` 只投影服务端已经缓存的 5 小时和 7 天窗口，不返回原始供应商载荷，也不会因用户打开目录而请求上游。管理员建立分组或精确授权后，窗口可同时带有请求数、Token、账号口径费用、标准费用和用户口径费用；统计严格限定在授权分组内，由服务端一次批量聚合，不提供用户身份或逐用户拆分。没有缓存快照时仍返回授权来源，但不伪造百分比或窗口统计。

### 3.3 账号名称脱敏

服务端在组装 DTO 前识别单个 `@`、无空白符且本地段/域名均非空的邮箱形式名称。识别成功时复用 `MaskEmail`：

```text
alice@example.com -> a***e@example.com
ab@example.com    -> a***@example.com
```

普通标签（例如 `Tokyo Pool 03`）保持原样。前端只消费已脱敏字符串，绝不在浏览器保存、请求或推断原始邮箱。

### 3.4 状态与用量口径

目录仅使用三种状态：

| 状态 | 含义 |
| --- | --- |
| `ready` | 当前可调度 |
| `cooling` | 账号仍有效，但速率限制重置时间尚未到达 |
| `unavailable` | 账号禁用、不可调度、过期、过载或临时不可调度；原因不向用户公开 |

状态优先级为“不可用”高于“冷却”：账号已被停用时，即便数据库残留未来重置时间，也只显示通用不可用。

用量始终标记范围：

- `rolling_24h`：公开账号在**同一分组**内近 24 小时的聚合请求数和 Token 数，避免把该账号在其他分组的流量带入。
- `personal_lease`：专属账号仅统计当前用户从本次分配开始至今的用量，避免新租约混入旧租约或共享池历史。

### 3.5 管理员用量细节授权

管理员在“账号分配控制 → 用量可见权限”管理两种授权：

1. `exclusive_group`：只允许选择当前活跃的专属分组。授权动态作用于当前及以后获得该分组访问资格的用户；用户失去分组权限或订阅过期后，目录查询会立即停止返回该分组及其细节。
2. `user_account`：绑定一个活跃用户、一个该用户当前可访问的分组和该分组中的一个账号。账号离开分组、被删除、被独占租约占用或用户失去分组访问资格后，授权不再产生可见结果。

授权只放大“上游缓存用量细节”字段，不放大目录账号集合，也不改变 API Key、计费、路由、调度和订阅权限。删除授权立即生效。数据库使用形状约束和部分唯一索引阻止非法组合及重复授权。

管理员接口：

```text
GET    /api/v1/admin/account-allocations/usage-visibility-grants
POST   /api/v1/admin/account-allocations/usage-visibility-grants
DELETE /api/v1/admin/account-allocations/usage-visibility-grants/:id
```

## 4. 查询与一致性要求

目录查询使用单个只读 SQL 请求，分别构造公开账号和专属账号后合并排序。它必须满足：

1. 公开列表用 `NOT EXISTS` 排除任何活跃分配租约，不让某个用户的专属账号出现在其他用户公开视图中。
2. 专属列表同时验证分配、策略、分组、账号、账号-分组关系和用户主体均为当前有效状态。
3. 订阅型专属账号使用 `user_subscriptions` 的 `active + expires_at > NOW() + deleted_at IS NULL` 条件。
4. 标准专属账号使用当前用户 `user_allowed_groups` 关联表复核，防止管理员后来回收分组权限后目录仍滞留旧分配；不依赖已弃用的 `users.allowed_groups` 列。
5. 前端筛选全部在已授权返回集上进行，不能以浏览器参数扩大服务端查询范围。

现有索引已经覆盖专属个人用量查询：`usage_logs(user_id, account_id, created_at)`。公开用量按账号、分组和近 24 小时聚合，目录不会新增写入或后台任务。

## 5. 前端信息架构

### 5.1 页面结构

页面沿用 `/account-allocations`，导航名称改为“账号目录”。内容按以下顺序展示：

1. 只读与隐私说明。
2. 四项摘要：公开分组数、专属分组数、可见账号数、当前可用账号数。
3. 控制条：搜索、来源、分组、平台、状态、刷新、行/网格视图切换。
4. 账号列表或网格卡片。
5. 只读详情弹窗。

刷新时保留已有数据，并以局部加载状态提示，不在数据已存在时把整页换成骨架，避免分页/刷新闪烁。

### 5.2 行显示

行显示用于管理员式快速横向比较，字段为：

| 列 | 显示内容 |
| --- | --- |
| 账号 | 已脱敏名称、公开/专属来源 |
| 分组 | 分组名称、标准/订阅类型 |
| 平台 / 类型 | 平台和认证类型 |
| 并发 | 可用并发容量 |
| 用量 | 请求 / Token 及其统计范围 |
| 状态 | 可用、冷却或暂不可用；冷却时显示预计恢复时间 |

整行可点击打开详情，不含选择框、更多菜单、编辑、删除、重置或同步按钮。

### 5.3 网格显示

网格显示适合快速浏览。卡片采用两列事实布局：来源、平台/类型、并发、用量。状态位于卡片标题区，底部保留短可用性提示和“查看详情”。

初始最多展示 24 张卡片；点击“再显示”追加下一批。行显示继续使用共享表格的虚拟化能力，因此可安全处理较多公开账号。

### 5.4 详情与移动端

详情弹窗展示脱敏名称、分组、来源、分组类型、平台/类型、并发、状态、限定口径用量、专属分配时间和冷却恢复时间。弹窗底部固定说明其隐私边界。

在小屏幕上：

- 筛选控件自动变为两列；
- 行表格复用响应式卡片呈现；
- 网格缩为单列；
- 所有文本使用截断和 `min-width: 0`，长邮箱不会压出布局。

用户最后一次选择的行/网格视图保存在本地 `user-account-directory-view-mode`，不涉及服务端偏好或隐私数据。

## 6. 非目标与后续扩展

本阶段不提供：

- 用户对账号的启停、删除、测试、刷新令牌、切换代理、调整并发或重新分配；
- 用户查看其他人的专属分配，或查看原始账户身份；
- 向浏览器下发模型列表和路由策略；
- 以目录替代订阅、余额、API Key 或网关授权。

以后如需扩展，可在不改变安全 DTO 的前提下增加：按分组的匿名容量汇总、用户自己的历史分配事件、管理员配置的公开目录公告、缓存 `ETag`/短轮询和导出用户本人可见的汇总报表。任何新增字段都必须先经过“是否会暴露上游账号身份、调度策略或其他用户行为”的审查。

## 7. 验证清单

后端单元测试覆盖：

- 邮箱名称服务端脱敏；
- 公开/专属用量范围不同；
- 专属账号仅显示自己的分配期与分配时间；
- 冷却与不可用状态优先级；
- 不向 DTO 传递账号内部标识。
- 专属分组整体授权与指定用户账号授权的输入形状、唯一性和访问资格；
- 未授权账号不投影缓存配额，撤销授权后查询不再命中。

前端验证应覆盖：

- 初次加载、保留数据刷新、错误后重试；
- 来源/分组/平台/状态/搜索的组合筛选；
- 行显示与网格显示切换及本地偏好恢复；
- 脱敏标识、详情无操作按钮、移动端响应式呈现；
- 公开账号和专属账号的统计口径标签。
- 管理员授权入口、授权来源标签和无缓存快照状态。
