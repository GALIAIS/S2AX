# 账号分配控制平面设计与验收

## 1. 目标

账号分配控制平面用于把指定分组中的健康空闲账号以排他租约分配给指定用户，并持续维持管理员配置的目标数量。它解决四个核心问题：

1. 管理员可以按“用户 + 分组”定义目标账号数。
2. 低于目标数量时自动从该分组补齐；达到或高于目标时停止自动增加。
3. 账号出现持久化 401、429、禁用、删除、到期或移出分组等情况时，按策略释放并补入其他空闲账号。
4. 用户可以查看公开账号及分配给自己的账号状态、容量和本人使用统计，但不能操作账号，也不能获得凭据、代理、内部 ID 或其他用户数据。

该能力不改变没有分配策略的用户。只有存在启用中策略的“用户 + 分组”才进入强制租约路由。

## 2. 数据模型

### 2.1 策略 `account_allocation_policies`

每个未删除的 `(user_id, group_id)` 只允许一条策略。

- `desired_count`：目标有效租约数，受服务端 `max_desired_count` 硬限制。
- `auto_replenish`：是否自动补齐；关闭后仍会释放失效租约。
- `replace_on_401`：是否释放已被本地健康状态明确识别为 401 的账号。
- `replace_on_429`：是否释放仍在 429 冷却窗口内的账号。
- `status`：`active` 或 `disabled`。
- `last_reconciled_at`：最近一次协调完成时间。
- `deleted_at`：软删除；历史租约和事件继续保留。

策略本身不授予分组访问权。专属分组权限或订阅不满足时，策略保留为启用状态但进入受阻状态，便于权限恢复后自动继续。

### 2.2 租约 `account_allocation_assignments`

租约状态只有 `active` 和 `released`。数据库唯一约束保证同一账号全局最多只有一个有效租约。

- 有效租约保存策略、用户、分组和账号快照关联。
- 释放后保存 `released_at` 与结构化 `release_reason`。
- 账号被删除时历史租约仍可审计，但管理员投影不再返回原账号标识和名称。

### 2.3 审计事件 `account_allocation_events`

所有控制面变更写入不可变事件：

- 策略创建、更新、启用、停用、删除；
- 自动或手动分配；
- 手动释放、健康释放、权限失效释放；
- 权限受阻。

事件包含操作者、租约、原因及来源，不保存账号凭据或上游原始响应体。

## 3. 不变量

系统必须始终满足以下条件：

1. 一个账号不能同时租给两个用户。
2. 租约账号必须属于策略分组。
3. 自动和手动分配只能选择未删除、启用、可调度、未到期、未过载、未处于临时禁用或 429 冷却的账号。
4. API Key/Bedrock 账号的持久化配额耗尽状态不能进入候选集。
5. 用户或分组不可用、专属权限被移除、订阅失效时，现有租约必须失败关闭。
6. 管理策略用户只能调度自己在该分组的有效租约；普通用户不能调度任何其他用户的有效租约。
7. 粘性会话复用账号前必须再次校验租约归属，不能绕过候选过滤。
8. 用户接口必须采用字段白名单，不能依赖前端隐藏敏感字段。

## 4. 访问状态

策略投影实时计算 `access_status`：

| 状态 | 含义 | 分配行为 |
| --- | --- | --- |
| `ready` | 用户、分组及访问资格正常 | 允许手动分配和自动补齐 |
| `user_unavailable` | 用户停用或删除 | 释放全部租约，禁止补齐 |
| `group_unavailable` | 分组停用或删除 | 释放全部租约，禁止补齐 |
| `group_access_required` | 缺少专属标准分组权限 | 释放全部租约，禁止补齐 |
| `subscription_required` | 缺少有效订阅 | 释放全部租约，禁止补齐 |

权限恢复后，启用且打开自动补齐的策略会在下一次后台协调或管理员“协调全部”时恢复目标容量。

## 5. 协调流程

单策略协调在一个数据库事务内完成：

1. 使用 `FOR UPDATE SKIP LOCKED` 获取策略锁；多实例并发时已有执行者的策略会被安全跳过。
2. 重新计算用户和分组访问状态。
3. 若访问受阻，释放该策略的全部有效租约并写入事件。
4. 检查每个有效租约：
   - 账号不存在、已删除、已移出分组、到期：始终释放；
   - 持久化 401：按 `replace_on_401`；
   - 429 冷却：按 `replace_on_429`；
   - 其他硬不可用状态：始终释放。
5. 统计剩余有效租约。
6. 打开自动补齐且低于目标时，从分组候选池按优先级和账号 ID 稳定选择，账号行使用 `FOR UPDATE SKIP LOCKED`。
7. 写入租约、事件及协调时间后提交。

管理员触发的“协调全部”会处理调用开始时全部符合条件的策略，不受后台批量大小限制。后台协调器按 `policy_batch_size` 处理最久未协调的一批策略，避免周期任务长时间占用数据库。

手动释放开启自动补齐的策略时，同一事务会优先从其他空闲账号补缺，并排除本次刚释放的账号。没有替代账号时保留真实缺口；下一轮协调才允许该账号重新成为候选。

## 6. 数据库即时生命周期保护

周期协调是兜底，不应成为权限撤销的唯一防线。迁移 `288_account_allocation_access_lifecycle.sql` 在以下写操作后立即释放租约：

- 删除 `user_allowed_groups`；
- 订阅状态、到期时间或软删除状态变化；
- 删除订阅；
- 用户从启用状态变为停用；
- 分组从启用状态变为停用。

账号、用户或分组软删除的原有触发器继续负责对应生命周期。时间自然流逝导致的订阅到期由周期协调器处理。

## 7. 网关接入

Anthropic、OpenAI 和 Gemini 兼容调度路径共享相同租约规则：

1. 正常调度器先执行平台、模型、健康与配额过滤。
2. 账号分配过滤器再按当前认证用户及请求分组过滤：
   - 有启用策略：只保留属于该用户、该分组的有效租约；
   - 无策略：排除所有已被其他用户租用的账号。
3. 粘性会话命中旧账号时调用 `CanUseAccount` 二次校验。
4. 分配服务或数据库查询失败时失败关闭，不回退到共享账号。

控制面协调不位于请求热路径，不增加上游首字延迟；请求热路径只执行租约归属查询。

## 8. 管理员控制面

管理员页面提供：

- 全局策略数、启用数、分配/目标容量、总缺口、受阻策略数；
- 状态、用户和分组筛选，用户选择支持服务端搜索；
- 新建、编辑、启停、删除、单策略协调、协调全部；
- 策略访问受阻原因；
- 当前和历史租约、释放原因、事件历史；
- 健康空闲候选账号的服务端搜索与手动分配；
- 手动释放及自动替代反馈。

列表刷新、分页和操作后更新会保留现有表格，不用整页加载态覆盖内容，避免闪烁。首次进入页面才显示表格骨架。

## 9. 用户只读目录

用户目录包括两类来源：

- 所有启用中非专属分组的公开账号；
- 当前用户仍有权访问的有效专属租约。

安全边界：

- 邮箱形账号名由后端打码；
- 不返回账号 ID、策略 ID、租约 ID、凭据、代理、IP、备注、原始错误、模型清单；
- 公开账号只显示同分组近 24 小时聚合用量；
- 专属账号只显示当前用户在本次租约窗口内的用量和费用；
- 上游配额只读取缓存快照，不因浏览目录请求上游，并且仅向专属租约用户显示白名单窗口。

## 10. 接口

管理员：

- `GET /api/v1/admin/account-allocations/capabilities`
- `GET /api/v1/admin/account-allocations/overview`
- `POST /api/v1/admin/account-allocations/reconcile`
- `GET|POST /api/v1/admin/account-allocations/policies`
- `GET|PUT|DELETE /api/v1/admin/account-allocations/policies/:id`
- `POST /api/v1/admin/account-allocations/policies/:id/status`
- `POST /api/v1/admin/account-allocations/policies/:id/reconcile`
- `GET /api/v1/admin/account-allocations/policies/:id/assignments`
- `GET /api/v1/admin/account-allocations/policies/:id/candidates`
- `POST /api/v1/admin/account-allocations/policies/:id/assignments`
- `DELETE /api/v1/admin/account-allocations/policies/:id/assignments/:assignmentId`
- `GET /api/v1/admin/account-allocations/policies/:id/events`

用户：

- `GET /api/v1/account-allocations/visible`
- `GET /api/v1/account-allocations`（兼容只读摘要）

所有用户接口从认证上下文取得用户 ID，不接受请求方传入其他用户 ID。

## 11. 配置与运维

```yaml
account_allocation:
  reconcile_interval_seconds: 15
  policy_batch_size: 100
  max_desired_count: 50
```

- `reconcile_interval_seconds`：1–300 秒；
- `policy_batch_size`：1–1000，仅限制后台单轮任务；
- `max_desired_count`：1–1000，限制单策略目标值。

运维排查顺序：

1. 查看概览中的受阻策略和缺口；
2. 查看策略的 `access_status`；
3. 查看租约释放原因与事件；
4. 检查分组内是否存在健康、空闲且未被其他策略租用的账号；
5. 执行单策略协调；批量故障恢复时执行协调全部。

## 12. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 创建目标数为 2 的自动策略 | 立即产生 2 个有效租约 |
| 重复创建同用户同分组策略 | 返回冲突 |
| 普通用户调度 | 只能得到自己的租约 |
| 其他用户调度 | 看不到已租账号 |
| 429 且开启替换 | 释放并补入其他健康账号 |
| 持久化 401 且开启替换 | 释放并补入其他健康账号 |
| 账号删除、解绑、禁用或到期 | 始终释放 |
| 手动释放且有空闲替代 | 同事务补入不同账号 |
| 撤销专属分组权限 | 数据库触发器立即释放，策略显示受阻 |
| 恢复权限并协调 | 自动恢复目标容量 |
| 关闭自动补齐 | 仍释放失效租约，但不补入 |
| 停用或删除策略 | 立即释放全部租约 |
| 用户只读目录 | 名称打码、无敏感字段、其他用户不可见 |
| 多实例同时协调 | 行锁避免重复分配 |

自动化覆盖包括服务单元测试、迁移检查、真实 PostgreSQL/Testcontainers 生命周期测试、前端组件测试及本地 Docker + Playwright 端到端测试。
